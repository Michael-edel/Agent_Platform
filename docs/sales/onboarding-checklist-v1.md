# Onboarding Checklist v1 — Pilot (Go/No-Go)

## 1) Доступы и ответственные

- [ ] Назначен **владелец пилота** (финансы) и **ИТ контакт** (клиент).
- [ ] Назначен **ответственный platform_admin** (со стороны CyberPlat).
- [ ] Канал коммуникации и эскалации: [placeholder] (чат/почта/телефон).
- [ ] Окно для weekly review согласовано (дата/время).

## 2) Tenant и окружение

- [ ] Tenant создан и активен (ID зафиксирован): [placeholder tenant_id].
- [ ] Окружение пилота определено: staging / production-like / production (по согласованию).
- [ ] `PUBLIC_BASE_URL` настроен (для webhook URLs).
- [ ] Для staging: `BILLING_DRY_RUN=true` (если используется для валидации).

## 3) 1С (MVP)

- [ ] Определён контур интеграции 1С (какие объекты/поля/операции входят в пилот).
- [ ] Доступ к тестовому контуру 1С предоставлен (endpoint/учётные данные).
- [ ] Согласованы требования по сети (VPN/allowlist/DNS).
- [ ] Предоставлен набор тестовых данных (20–50 сущностей или согласованный объём).
- [ ] Smoke-проверка: создание job → обработка → результат (succeeded/failed с кодом).

## 4) Банк / выписки / форматы

- [ ] Согласован источник выписок и формат (CSV/иное), 1–2 формата в пилоте.
- [ ] Предоставлен пример выписки (реальный/обезличенный) + правила парсинга.
- [ ] Согласованы правила сопоставления (amount/date/purpose/counterparty).
- [ ] Smoke-проверка: импорт выписки → видны транзакции → возможен match.

## 5) Платежи и согласование

- [ ] Согласована матрица согласования (роли, шаги, SLA на утверждение).
- [ ] Согласованы статусы и “что считается завершением” (exported, paid, reconciled).
- [ ] Определён формат экспорта (CSV/1С) и место хранения (локально/S3 — если включено).
- [ ] Smoke-проверка: создать payment order → approve → export.

## 6) Безопасность и комплаенс (минимум для пилота)

- [ ] Подтверждена tenant isolation (данные пилота не смешиваются с другими tenant).
- [ ] Webhook allowlist/подписи подтверждены (если применимо).
- [ ] Доступы к админке ограничены и выданы только нужным ролям.
- [ ] Порядок работы с инцидентами и логами согласован (без передачи секретов).

## 7) Observability и готовность к эксплуатации

- [ ] Prometheus собирает метрики (app/worker).
- [ ] Grafana доступна и дашборды загружаются.
- [ ] Базовые алерты включены (worker, queue, failure spike).
- [ ] SLO (time-to-paid ≤ 5m) включён (recording rules + burn-rate alerts), если входит в пилотный контур.

## Go/No-Go критерии (готовность к старту пилота)

**Go**, если выполнено:
- [ ] есть ответственные и канал эскалации;
- [ ] tenant создан и окружение готово;
- [ ] 1С доступна и smoke по jobs проходит;
- [ ] выписка импортируется и транзакции видны;
- [ ] payment order проходит согласование и экспорт;
- [ ] observability доступна (минимум: метрики/дашборд).

**No-Go**, если:
- нет доступов к 1С или банк-выписке;
- не определён формат/объём пилота;
- нет ответственных и согласованного окна поддержки;
- невозможно обеспечить минимальные требования безопасности (allowlist/доступы).
