# 1С Trust Bridge (Phase 3)

Цель: тонкий мост подтверждений между системой и учётом (1С), без «интеграционного ада».

## 1) Export summary (read-only)

`GET /api/v1/integrations/1c/payments/{payment_id}/summary` (tenant-scoped)

Возвращает краткую сводку по платежу:
- `payment_id`, `tenant_id`
- `state` (например: `APPROVED`, `SENT`, `RECONCILED`, `FAILED`)
- `amount`, `currency`
- `document_id` (если есть), `case_id` (если есть)
- `timeline.created_at / approved_at / reconciled_at` — вычисляется из событий (timeline)

## 2) Import confirmation (write, idempotent)

`POST /api/v1/integrations/1c/payments/confirm` (tenant-scoped, `X-Tenant-ID`)

Payload:

```json
{
  "payment_id": "uuid",
  "external_id": "1c-12345",
  "result": "CONFIRMED",
  "confirmed_at": "2026-01-15",
  "reason": "optional"
}
```

Правила:
- `CONFIRMED` → переводит payment в `SENT` (если payment уже `RECONCILED`, состояние не понижается) и пишет событие `payment.sent`
- `REJECTED` → переводит payment в `FAILED` и пишет событие `payment.sent_failed` (`reason` обязателен)
- идемпотентность: повторный `confirm` с теми же `(tenant_id, payment_id, external_id, result)` не создаёт дублей событий
